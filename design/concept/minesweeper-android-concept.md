## 0. 结论先行（TL;DR）

1. **内核可完整复用**：雷区生成（首击安全）、洪水展开、chord、胜负判定、最佳成绩持久化均为纯 Python，本期只需重写 Kivy 的 UI 层，不重造玩法逻辑。
2. **设计三大支柱**：① 原汁原味经典扫雷内核；② 触屏极简单手操作；③ 复古像素美学在触屏的清晰演进。
3. **新功能推荐（本期优先做）**：**每日挑战**（复杂度低、耦合高，ROI 最高）→ **成就系统**（复杂度低、耦合中）→ **提示与复盘**（复杂度中、耦合高，放期望层）→ **本地排行榜**（复杂度低、耦合低，候补，可后续扩在线）。**不推荐本期做**：联机对战（复杂度高、偏离内核）、皮肤/主题商城（涉及内购广告变现，Kivy 链路复杂）。
4. **最大风险**：触屏右键缺失、30×30 大棋盘格子过小、Kivy 大棋盘 Widget 性能、递归洪水在移动端栈溢出、单手可达性。均有明确缓解方案（见 §7）。

| 现有能力 | 所在代码 | 安卓版处理 |
|----------|----------|------------|

| 数字格连开 chord | `chord()` | 直接复用，触屏交互重新映射（§7） |
| 右键循环标记 | `on_right()` 无→旗→?→无 | 触屏改为长按 / 模式切换 |

| 最佳成绩本地持久化 | `best.json`（`%LOCALAPPDATA%`） | 迁移到 Android 内部存储 / 共享存储路径 |

## 2. 设计支柱（Pillars）

| # | 支柱 | 一句话 | 落地约束 |
|---|------|--------|----------|
| P1 | **经典内核 fidelity** | 玩家在手机上玩到的，就是他记忆里那款扫雷 | 首击安全、洪水、chord、胜负、计时、10 难度一个不能砍；数值规则与桌面版完全一致 |
| P2 | **触屏极简 / 单手友好** | 一只手、拇指可及，误触可救 | 翻开/标记双操作必须单手完成；大棋盘可缩放平移；提供撤销；HUD 底部化 |
| P3 | **复古像素 · 清晰演进** | 经典灰 + 像素硬边在 high-DPI 屏依然锐利 | 保留 3D 凸起/凹陷、像素红旗黑雷黄笑脸；提供 light/dark 双主题；触控态凹陷反馈 |

> 支柱漂移红线：任何新功能若破坏 P1 的数值规则，或让 P2 操作变复杂（如强制双手），即判为偏离，需回主理人。

## 3. MDA 分析

### Mechanics（机制 · 能做什么）
- 棋盘状态：未翻开 / 已翻开（数字 0–8 或空） / 旗 / 问号 / 雷。
- 操作原语：翻开（左键）、标记循环（右键）、连开（chord）、重开（笑脸）。
- 系统：布雷（首击安全 3×3 禁区）、邻接计数、洪水 BFS、胜负判定、计时、难度配置、主题、最佳成绩。
- **安卓映射**：翻开=点按；标记=长按或工具栏「标记模式」；连开=双击已翻开数字格（或长按数字格）；重开=底部 HUD 笑脸。

### Dynamics（动态 · 玩起来怎样）
- 推理链：数字 → 邻域雷数 → 排除/锁定 → 形成推理快感。
- 旗的博弈：旗既是记忆也是「保险」，chord 把旗转化为提速手段（高手用 chord 秒清）。
- 风险曲线：首击后进入稳定推理期，越接近终盘越紧张；误插旗会在终盘 chord 时反噬。
- **触屏新增动态**：标记模式切换带来「节奏切换」手感；缩放平移在高难度引入空间导航成本（需平衡）。

### Aesthetics（美学 · 玩家获得什么）
按 LeBlanc 八美学映射：
- **Challenge（挑战）**：逻辑推理与速度压力的满足——主美学。
- **Discovery（发现）**：洪水展开揭示版图的爽感。
- **Accomplishment（成就）**：刷新最短用时、通关高难度的成就感（为成就系统埋点）。
- **Sensation（感官）**：复古像素 nostalgia，硬边图标带来的「老软件」质感。
- （Expression / Submission / Fantasy 非本期重点，不做。）

> 美学优先级：**Challenge > Accomplishment > Discovery > Sensation**。新功能优先服务前三者。

## 4. 范围分层

### 核心（MVP · 必须交付）
- Kivy 重写 UI，封装现有核心逻辑为独立 `core/` 模块（与 UI 解耦）。
- 10 档难度（沿用 `LEVELS`，先修 README/代码不一致）。
- 触屏操作：点按=翻开；长按=插旗（默认）；chord=双击/长按已翻开数字格。
- 首击安全、洪水展开、chord、胜负判定全部复用并验证一致。
- 计时（封顶 999）+ light/dark 双主题。
- 最佳成绩本地持久化（迁移 Android 存储路径）。
- 难度切换 UI（移动端底部抽屉/选单）、胜利/失败反馈（复用笑脸四态）。
- HUD：笑脸 / 剩余雷数 LCD / 计时，底部化、拇指可达。

### 期望（Should · 体验闭环）
- 新手首玩引导（3 步教点按/长按/chord）。
- 大棋盘缩放 + 平移（pinch-zoom / drag-pan）。
- 单手模式 + 撤销一步（救误触）。
- 无障碍：色盲安全数字配色、放大点击区、高对比主题。
- 触觉反馈（插旗/踩雷/胜利震动）。
- 问号标记保留且可关。

### 锦上添花（Could · 新功能层，见 §6）
- 每日挑战、成就系统、提示与复盘、本地排行榜、自定义种子分享、桌面 Widget。

## 5. 移动端视觉锚点（交付美术负责人）

**目标**：把 Windows 95 风格灰盒像素扫雷，在手机 high-DPI 触屏上「锐利还原 + 适度演进」，不糊、不土、不丢记忆点。

### 5.1 必须保留的记忆符号（硬资产）
| 资产 | 原版特征 | Kivy 还原要求 |
|------|----------|---------------|
| 格子斜面 | base `#c0c0c0`，左上白高光 `#ffffff`，右下暗灰 `#808080` | 用 Canvas 斜角指令，保留 1px 硬边；按下态反转为凹陷 |
| 像素红旗 | 红三角旗面 `#ff0000` + 深灰旗杆 | 硬边绘制，禁用抗锯齿模糊 |
| 黑色地雷 | 黑圆 + 四向刺 + 左上高光点 | 同原版；爆炸态加红底 |
| 像素笑脸 | 黄圆脸 + 黑眼 + 折线嘴（smile/dead/cool/press 四态） | 四态全保留，press 态即触屏按下反馈 |
| 数字 1–8 | 经典配色（1蓝 2绿 3红 4深蓝 5暗红 6青 7黑 8灰） | 沿用；另出一套**色盲安全**配色（期望层） |
| LCD 红字 | 黑底红字 `#ff0000` 等宽 | 雷数/计时 HUD 复用 |

### 5.2 演进建议（不破坏记忆点）
- **清晰度优先**：所有图标用矢量/atlas 按 `@2x/@3x` 生成，或运行时按 `dp` 绘制，避免位图拉伸模糊。
- **触控态反馈**：按下时格子即时凹陷 + 轻微缩放，给「按下了」的确认感（替代桌面 hover）。
- **主题扩展（本期仅 light/dark）**：dark 主题沿用代码 `#2d2d3a` 系；预留「霓虹 / 糖果」主题接口，但本期不产出额外皮肤资产。
- **板面留白**：触屏需更大点击热区，格子视觉可略大于桌面 20px 等效，但保持方格硬边。

### 5.3 给美术的资产交付清单（待产出）
笑脸四态、红旗、地雷（普通/爆炸）、问号、数字 1–8（light/dark 各一套）、HUD 面板（凸起灰）、图标（重开/难度/主题/设置）。统一提供 SVG 源 + 多分辨率位图 + Kivy 配色常量表。

## 6. 新功能候选方向（2–4，含推荐排序）

> 评选维度：玩家价值、实现复杂度（低/中/高）、与现有玩法内核耦合度（高=直接复用核心逻辑，低=几乎独立层）。**全部候选均不破坏 P1 数值规则。**

### 候选 1 · 每日挑战（Daily Challenge）★ 推荐第 1
- **一句话定义**：每天全网同一棋盘种子，限时比拼最短通关时间。
- **玩家价值**：固定目标带来日常回访与社交可比性（"今天你几秒？"），零学习成本。
- **复杂度**：**低**——仅需把 `place_mines` 的 `random` 改为按日期种子（`random.Random(seed)`），复用全部核心逻辑；本地存每日最佳。
- **耦合度**：**高**——直接复用布雷/洪水/chord/胜负，仅加 seed 入参与每日榜单。
- **为何排第 1**：ROI 最高，1–2 天可落地，且为后续在线排行榜天然铺垫。

### 候选 2 · 成就系统（Achievements）★ 推荐第 2
- **一句话定义**：基于难度/胜利/用时/连开等事件解锁徽章（如「首次通关」「专家 100 秒内」「单局 chord ≥ 20 次」）。
- **玩家价值**：把零散游玩转化为目标感与成长反馈，提升留存（服务 MDA 的 Accomplishment）。
- **复杂度**：**低–中**——监听 `check_win` / 计时 / chord 计数，写本地成就表；UI 为徽章墙。
- **耦合度**：**中**——需核心层在胜利/踩雷/chord 时抛出事件，但核心数值不变。
- **为何排第 2**：低成本补强成就感美学，与内核天然契合。

### 候选 3 · 提示与复盘（Hint & Replay）★ 推荐第 3（期望层）
- **一句话定义**：提供「安全格高亮」提示与「本局操作回放/踩雷前一步」复盘。
- **玩家价值**：降低新手劝退率（提示），老手用复盘精进推理（服务 Challenge/Discovery）。
- **复杂度**：**中**——提示需基于已翻开信息做确定性安全格推导（避免泄雷破坏公平性）；复盘需记录操作序列。
- **耦合度**：**高**——深度读取 board/revealed/flagged 状态，与核心强相关。
- **为何排第 3**：价值高但实现较重，放期望层，不阻塞 MVP。

### 候选 4 · 本地排行榜（Local Leaderboard）★ 推荐第 4（候补，可后续扩在线）
- **一句话定义**：按难度记录本地前 N 成绩（时间/日期），支持后续联网同步。
- **玩家价值**：把「最佳成绩」从单值升级为可翻看的榜单，增强挑战动机。
- **复杂度**：**低**（本地）/ **高**（在线，需后端+账号）。
- **耦合度**：**低**——只读 `best` 类数据，几乎独立层。
- **为何排第 4（候补）**：本期建议先做本地版（低成本），在线版留待后续平台扩展时再做；不阻塞内核。

### 不推荐本期
- **联机对战**：复杂度高、与单人对战内核耦合低、需实时网络，偏离 P1，本期不做。
- **皮肤/主题商城**：涉及内购/广告变现，Kivy 在安卓的变现链路复杂；且本期资产仅 light/dark 两主题，无商城内容，本期不做。

## 7. 已知风险与缓解

| # | 风险 | 影响 | 缓解方案 |
|---|------|------|----------|
| R1 | **触屏无右键** | 标记/问号操作缺失 | 默认长按=插旗；底部工具栏「挖掘/标记」模式切换；chord 映射为双击已翻开数字格（或长按数字格）；提供撤销救误触 |
| R2 | **大棋盘格子过小**（30×30=900 格） | 看不清、误触 | pinch-zoom + drag-pan；高难提供「聚焦缩放」；点击热区大于视觉格 |
| R3 | **Kivy 大棋盘性能** | 卡顿/掉帧 | 不用 900 个独立 Widget；用**单个棋盘 Widget + Canvas 指令重绘**，仅重绘变更格；洪水展开批量重绘而非逐格 |
| R4 | **递归洪水栈溢出** | 移动端 Python 递归上限，大空区崩溃 | 把 `reveal()` 递归改为**显式栈（iterative BFS）** |
| R5 | **单手可达性** | 顶部 HUD 难够 | HUD（笑脸/雷数/计时）与难度切换全部**底部化**，拇指热区覆盖 |
| R6 | **Android 生命周期** | 切后台计时错乱 | 接 `on_pause`/`on_resume` 暂停/恢复计时与状态 |
| R7 | **像素图标在 high-DPI 模糊** | 失忆点、显廉价 | 矢量/atlas 多分辨率绘制，硬边抗锯齿关闭，按 `dp` 出图 |
| R8 | **README 与代码难度不一致** | 端口数据来源不清 | 以 `minesweeper.py` 的 `LEVELS` 为唯一真源重制难度表（README 的 入门 8×8/10 等旧值作废） |
| R9 | **首击安全与自定义上限** | 自定义棋盘过小无法保证安全 | 复用 `ask_custom` 的 `max_mines = rows*cols-9` 限制逻辑 |
