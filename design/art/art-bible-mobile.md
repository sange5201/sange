# 扫雷 Minesweeper · 移动端美术圣经（Art Bible — Mobile / Kivy）

> **文档状态**：Phase 1 / Lean 评审稿，与游戏概念并行
> **负责人**：林绘澄（美术总监）
> **适用范围**：安卓版（Kivy + 触屏），适配移动端屏幕、明暗双主题、可访问性
> **视觉锚点**：经典 Windows 扫雷复古像素风 —— 3D 凸起/凹陷格子、像素红旗、黑色地雷、像素笑脸按钮、红/蓝/绿数字配色
> **一致性来源**：现有 Windows 版 `minesweeper.py`（Tkinter Canvas 逐像素绘制）——本 Bible 的所有图标几何均直接移植其归一化坐标公式，保证 brand 统一

---

## 结论先行（一页纸摘要）

1. **视觉身份不变**：移动端沿用 Windows 版的"灰色复古 + 像素图标 + 笑脸"语言，不另起炉灶；变化只在**尺寸基准、触屏热区、双主题对比度、可访问性冗余**。
2. **图标零位图资产**：延续「Canvas 程序化绘制」哲学，Kivy 下用 `Line/Rectangle/Ellipse/Triangle` 重绘，不依赖系统字体/emoji/图片，跨设备一致。
3. **像素网格法**：每个图标在以格为单位的 **16×16 虚拟像素网格**上定义，按比例缩放，保证任意 DPI 下像素比例一致、边缘锐利。
4. **触屏热区**：常规棋盘单格 `44–56dp`；超大棋盘（30 列）单格会 <44dp，默认启用 **ScrollView 滚动 + 可选 pinch-zoom** 到舒适尺寸。顶部计数器/笑脸/计时器各自 ≥44dp 高。
5. **手势映射**：单指点按=翻开；**长按≈350ms（环形进度+轻震动）=循环标记**；**双击已翻开数字格=连开(chord)**；笑脸按钮=重开。
6. **双主题对比度**：保留经典灰(亮)与护眼深(暗)，但移动端提高 bevel 与数字对比，满足可读性；数字沿用经典 1–8 配色作为默认，提供**色盲辅助开关**做冗余编码。

## 一、定位与情绪（Positioning & Mood）

| 维度 | 定义 |

### 2.3 触屏对比度与可读性
- **LCD 计数器**：红字(`#ff0000`/`#ff6b6b`) 配纯黑底(`lcd_bg`)，对比度 > 7:1，满足 WCAG AAA。
- **数字格**：数字绘制在已翻开（凹陷）格上，底色为 `BG`；经典 1(蓝)/3(红) 在 `#c0c0c0` 上对比约 3–4:1。移动端将**数字字重加粗 + 字号放大**（见第五节），并依赖形状/位置而非纯色（见第八节）。
- **bevel 可见性**：桌面用 1px 线；移动端 bevel 厚度按比例放大（见第三节），确保触屏距离下 3D 斜角清晰。
- **最小对比底线**：任何文字/图标与底色 ≥ 4.5:1（WCAG AA）；仅装饰性元素可放宽。

## 三、图形语言（Graphic Language）— 像素 / 复古

1. **3D 斜角 bevel（核心识别元素）**
   - 凸起格（未翻开）：左上 `BEVEL_LIGHT` 1px 线 + 右下 `BEVEL_DARK` 1px 线，内部填 `BG`。
   - 凹陷格（已翻开）：左上 `BEVEL_DARK` + 右下 `BEVEL_LIGHT`（反相），内部填 `BG`。
   - **移动端 bevel 厚度**：`bevel_dp = max(2, round(cell_dp / 10))`，保证放大后仍具体积感、不糊成细线。
2. **像素图标 = 程序化绘制**：不引入 PNG/SVG 位图。地雷/红旗/笑脸全部用 Canvas 图元（线、矩形、椭圆、三角）按归一化坐标绘制 → 与 Windows 版逐项一致，且**无锯齿一致性问题（矢量天生锐利）**。
3. **虚拟像素网格法**：每个图标在 **16×16 虚拟像素网格**（坐标归一到 [0,1]）上定义一次，按当前 `cell_dp` 等比缩放。例：红旗旗杆 `x=0.32`，旗面顶点 `(0.32,0.20)→(0.78,0.40)→(0.32,0.58)` —— 与 `minesweeper.py::draw_flag` 完全同构。
4. **禁用模糊滤镜**：Kivy 下不使用 `mag_filter='linear'` 缩放位图；纯图元绘制天然清晰。若后续引入图标 atlas，须 `mag_filter='nearest'` 保持像素硬边。
5. **留白与密度**：棋盘格**零间隙**（格与格紧贴，靠 bevel 分界），还原经典紧凑感；仅顶部信息栏与屏幕边缘保留 8–16dp 留白。

## 四、图标规范（Icon Spec）— Kivy Canvas 绘制规格与尺寸基准

### 4.1 尺寸基准（响应式 `cell_dp`）
| 常量 | 值(dp) | 说明 |
|------|--------|------|
| `MIN_TAP_DP` | 44 | 触屏最小建议热区（WCAG/ Material） |
| `CELL_MIN_DP` | 30 | 单格绝对可见下限（超大棋盘时） |
| `CELL_MAX_DP` | 56 | 单格舒适上限 |
| `FACE_DP` | 48 | 顶部笑脸按钮边长 |
| `COUNTER_W/H` | 72×44 | 雷数/计时 LCD 控件 |
| `bevel_dp` | `max(2, round(cell/10))` | 斜角线宽 |

**单格尺寸逻辑**：
```
avail = min(视口宽, 视口高 - 顶部栏 - 边距)
cell_dp = clamp(round(avail / max(rows, cols)), CELL_MIN, CELL_MAX)
if cell_dp < MIN_TAP_DP:   # 大棋盘(如30列)必然进入
    启用 ScrollView（棋盘在视口内双轴滚动）+ 可选 pinch-zoom 放大到 ~48dp
```
> 桌面原版固定 `CELL=20px`（远小于触屏热区），移动端必须放大；大棋盘以「滚动/缩放」换取单格可点性，而非强行压缩到不可点。

### 4.2 各图标绘制规格（归一化坐标，移植自 `minesweeper.py`）
所有图标绘制在单格 Canvas 上，背景先画 bevel 再画内容。

**① 红旗 `draw_flag`**（凸起底）
- 旗杆：`Line` 从 `(0.32,0.20)` 到 `(0.32,0.82)`，宽 `max(2, cell/10)`，色 `BEVEL_DARK`。
- 旗面：`Triangle`/`Polygon` 顶点 `(0.32,0.20)→(0.78,0.40)→(0.32,0.58)`，填充 `RED`。

**② 地雷 `draw_mine`**（凹陷底；`exploded` 时先填 `RED` 再画凹陷框）
- 中心 `(0.5,0.5)`，半径 `r = 0.22 * min(w,h)`。
- 4 条正交刺：从 `r*1.1` 到 `r*1.9` 的 `Line`，色 `BLACK`，宽 `max(2, cell/10)`。
- 主体：`Ellipse` 半径 `r`，填充/描边 `BLACK`。
- 高光：左上 `Ellipse` 半径 `r*0.4→r*0.12` 偏移，填充 `BEVEL_LIGHT`（暗主题下用更亮灰保证可见）。

**③ 错误旗 `draw_wrong_flag`**（游戏结束揭示）：凹陷底 + 红色叉（两对角 `Line`）+ 半透明旗杆轮廓，提示"此处插旗但非雷"。

**④ 问号 `draw_question`**（凸起底）：居中 `?`，色 `BLUE`，粗体，字号 `≈ cell*0.7`。

**⑤ 数字 `draw_number`**（凹陷底）：居中数字 `1–8`，色取第二节 2.2 配色，粗体，字号 `≈ cell*0.72`。

**⑥ 笑脸 `draw_face`**（顶部栏，`FACE_DP=48`）：黄色 `Ellipse` 脸盘 + 两眼黑点 + 嘴形折线，4 态：
- `smile`：上弧嘴（游戏进行）
- `press`：小圆嘴（按下瞬间）
- `dead`：下弧嘴（踩雷）
- `cool`：直线嘴（胜利，可加像素墨镜条）

> 笑脸与格子共用同一套 bevel 绘制函数（`_raised_box`），仅在脸盘与五官上叠加，保证"按钮也是格子"的经典观感。

## 五、排版（Typography）

| 用途 | 字体 | 尺寸 | 说明 |
|------|------|------|------|
| 格子数字 (1–8) | 等宽（monospace，Kivy 默认或捆绑像素等宽字体） | `≈ cell_dp * 0.72`，粗体 | 对齐经典 Courier 数字感；捆绑像素字体可强化复古（可选） |
| 问号标记 | 同上等宽 | `≈ cell_dp * 0.7`，粗体 | 蓝 |
| LCD 计数器（雷数/计时） | 数字等宽（捆绑 7-seg/点阵字体更佳） | `18sp` 粗体 | 红字黑底，3 位定宽 |
| UI 文本（难度名、按钮、弹窗） | 系统无衬线（默认） | `14–16sp` | 仅 UI 层用现代字体，棋盘内保持复古 |

- **单位**：界面文本用 `sp`（随系统字体缩放）；几何尺寸用 `dp`（密度无关）。Kivy 通过 `kivy.metrics.dp/sp` 接入。
- **可读性**：数字加粗 + 适当放大，避免小屏细字；暗主题数字提亮（见 2.2）。

## 六、节奏与间距（Rhythm & Spacing）— 触屏热区 ≥44dp

| 元素 | 间距/尺寸 | 规则 |
|------|-----------|------|
| 棋盘格间隙 | 0 dp | 紧贴，靠 bevel 分界（品牌） |
| 屏幕外边距 | 8–16 dp | 顶部栏与边缘留白 |
| 顶部栏高度 | ≥ 48 dp | 计数器/笑脸/计时器各 ≥44dp 热区 |
| 顶部栏三件套 | 计数器(72) · 笑脸(48) · 计时(72) + 间隙 | 总宽 ≈ 200dp，适配 ≥360dp 屏宽 |
| 单格热区 | `cell_dp`（见 4.1） | 常规 ≥44dp；<44dp 时靠滚动/缩放补偿 |
| 间距刻度 | 4 / 8 / 12 / 16 / 24 dp | 全局统一节奏 |

**触屏要点**：长按标记（见附录 A）对精度宽容，但"翻开"点按需单格可达；大棋盘用滚动而非压缩，避免热区塌缩。

## 七、动效原则（Motion）— 翻开 / 插旗 / 爆炸反馈

> 原则：短、脆、复古；不拖泥带水。统一用 Kivy `Animation`/`Clock`，时长 ≤ 200ms。

| 事件 | 视觉反馈 | 时长 | 说明 |
|------|----------|------|------|
| 翻开单格 | 凸起→凹陷 bevel 翻转 + 轻微缩放淡入 | ~120ms | 即时确定感 |
| 洪水展开 | 从点击点向外**阶梯级联**（每格 +20ms 延迟） | 总 ≤ 400ms | "扫"的爽感 |
| 插旗 | 红旗带轻微 overshoot 弹入 + LCD 雷数 -1 跳动 | ~150ms | 标记确认 |
| 取消旗/问号 | 快速淡出 | ~100ms | — |
| 连开(chord) | 从中心向外的涟漪/环形扩散 | ~200ms | 强调批量展开 |
| 踩雷 | 触发格闪红 → **屏幕抖动**(2–4dp, ~200ms) → 全盘淡入揭示 | ~300ms | 失败冲击 |
| 胜利 | 笑脸变 cool + 全盘红旗轻快逐个亮起 | ~500ms | 成就反馈 |
| 笑脸按压 | `press` 嘴形（o）瞬间切换 | ~80ms | 按钮反馈 |

**可访问性开关「减少动态效果」**：关闭抖动/缩放/视差，仅保留即时状态切换（见第八节）。

## 八、可访问性基础（Accessibility）— 色盲友好 + 对比度

### 8.1 对比度
- 文字/图标 vs 底色 ≥ 4.5:1（AA）；LCD 计数器 ≥ 7:1（AAA）。
- 暗主题所有前景色已提亮（2.2/2.3），避免深底上看不清。

### 8.2 色盲友好（关键）
经典 1(蓝)/2(绿)/3(红)/4(深蓝)/5(褐红)/6(青)/7(黑)/8(灰) 在**红绿色盲(deuteranopia/protanopia)**下易混淆（红绿、深蓝褐红、黑灰）。应对：
- **地雷/红旗不依赖纯色**：地雷=黑圆+刺（形状编码），红旗=旗杆+三角（形状编码），本身色盲安全。
- **数字提供「色盲辅助」开关（推荐方案）**：开启后切换为 **Okabe-Ito 安全色板** 并对每个数字叠加**形状/底点冗余**（如数字下方小方块数量=该数字），保证仅凭明度/形状即可区分。
- **默认态**保留经典配色（品牌）；色盲开关作为可选项，UX 规格须引用本分级。

### 8.3 触控与反馈
- 长按标记带**环形进度 + 轻震动(haptic)**，让用户明确进入标记模式（避免误触）。
- 最小热区 ≥44dp（见第六节）；大棋盘用滚动/缩放保障可点。
- 文本/计数器随系统字体 `sp` 缩放，支持系统大字体。

### 8.4 减少动态效果
- 开关：关闭抖屏/缩放/级联，保留状态即时切换，惠及前庭敏感用户。

### 8.5 屏幕阅读器（未来项）
- 预留单元格状态播报接口（"第 r 行 c 列，已翻开，数字 3 / 已插旗 / 未翻开"），本期可不实现，标注为路线图。

## 九、资产、命名与渲染管线（Kivy 性能预算）

### 9.1 资产策略（极简）
- **零位图资产**：所有图标/bevel 由 Canvas 图元绘制（同 Windows 版哲学）→ 包体最小、跨设备一致、无加载延迟。
- **可选字体资产**：若捆绑像素等宽字体 / 7-seg LCD 字体，置于 `assets/fonts/`，命名 `font_<用途>_<风格>.ttf`。

### 9.2 命名规范
| 类别 | 规范 | 示例 |
|------|------|------|
| 绘制函数 | `draw_<图标>` | `draw_flag`, `draw_mine`, `draw_face` |
| 主题令牌 | `THEMES[<light|dark>][<TOKEN>]` | `THEMES['dark']['BG']` |
| 尺寸常量 | `<NAME>_DP` | `CELL_DP`, `FACE_DP`, `bevel_dp` |
| 状态枚举 | `<state>` 小写 | `smile/press/dead/cool` |

### 9.3 渲染管线（Kivy）
- 棋盘容器：`ScrollView` 包裹 `GridLayout`（双轴滚动应对大棋盘）；或 `Scatter` 支持 pinch-zoom。
- 每格：`Widget` + 自带 `Canvas`，`on_touch_*` 处理点按/长按/双击。
- 重绘策略：状态变更仅 `canvas.clear()` + 重画该格（同 Windows 版 `refresh_cell`），不重画全盘。
- 性能预算（中端安卓）：
  - 单屏绘制调用 < 2000；30×30=900 格时，仅可见视口内格参与绘制（ScrollView 懒渲染）。
  - 动画并发 < 50 个 `Animation`；洪水级联用 `Clock.schedule` 节流。
  - 目标帧率 60fps，bevel/图标绘制开销极低（图元为主）。

| 首击安全 | 同桌面（首次点按触发布雷） | 首次点按即安全区，无特殊视觉 |

## 附录 B：与 Windows 版视觉一致性核对表

| 维度 | Windows 版 (`minesweeper.py`) | 移动端 (本 Bible) | 一致性 |
|------|-------------------------------|-------------------|--------|
| 3D 斜角 bevel | `_raised_box`/`_sunken_box`，1px 双色线 | 同算法，线宽按 dp 放大 | ✅ 同构 |
| 红旗 | `draw_flag` 杆+红三角 | 归一化坐标完全移植 | ✅ 一致 |
| 地雷 | `draw_mine` 黑圆+4刺+高光 | 同；暗主题高光提亮 | ✅ 一致 |
| 错误旗 | `draw_wrong_flag` 红叉 | 同 | ✅ 一致 |
| 问号 | `draw_question` 蓝? | 同 | ✅ 一致 |
| 数字 1–8 配色 | `THEMES['light/dark']['NUM']` | 2.2 表原样沿用 | ✅ 一致 |
| 笑脸 4 态 | `draw_face` smile/press/dead/cool | 同 4 态 + 可选墨镜 | ✅ 一致 |
| 双主题 | light(经典灰)/dark(护眼深) | 同令牌，仅对比度校正 | ✅ 一致 |
| 像素/程序化绘制 | Canvas 逐像素，无位图 | Kivy Canvas 图元，无位图 | ✅ 哲学一致 |
| 单格尺寸 | 固定 20px | 响应式 44–56dp（触屏放大） | ⚠️ 必要调整 |
